# 扩展侧边栏历史与关闭保活

## Goal

在 GitHub 仓库页的 content script 侧边栏中，用户关掉小报后仍能恢复内容，并能从「最近」列表回看已出报仓库；同仓再次点击「八卦小报」默认复开缓存，避免无谓重复打 LLM。

## Background

- 面板关闭当前为 `×` → `el.remove()`（`apps/extension/content.js`），内容与 DOM 一并销毁。
- 「八卦小报」每次点击均 `GOSSIP_FETCH`，无本地复开路径。
- 扩展已使用 `chrome.storage.local`（按钮位置、选项/BYOK）。
- 范围仅 GitHub content script 侧边栏；不含 Web / CLI / 跨设备同步。

## Decisions

| 决策 | 结论 |
|------|------|
| 同仓再点「八卦小报」 | 有历史则复开；面板内「重新出报」才打 API |
| 历史持久化 | `chrome.storage.local`，最近 20 条，按 `owner/repo` 去重只留最新 |
| 面板收缩 | MVP 不做；仅隐藏保活 + 最近历史 |

## Requirements

1. **关闭保活**：`×` 隐藏面板（不销毁内容）；再次通过「八卦小报」或「最近」可显示同一内容，无需重新请求。
2. **最近历史**：面板 header 提供「最近」入口，列出已缓存仓库（至少 repo、标题摘要、时间）；点选即复开对应小报。
3. **同仓复开**：当前页仓库若已有成功缓存，点「八卦小报」直接展示缓存并显示面板。
4. **重新出报**：成功小报视图内提供「重新出报」；成功后写入/覆盖该仓历史条目。
5. **写入规则**：仅成功响应写入历史；失败/加载中不入库。上限 20；超出按最旧淘汰。同仓覆盖为最新。
6. **跨会话**：刷新 GitHub 或重启浏览器后，「最近」仍可打开已存条目。

## Acceptance Criteria

- [ ] AC1：出报成功后点 `×`，面板消失；再点「八卦小报」（同仓）立刻复开同一内容，网络层无新的 `GOSSIP_FETCH`。
- [ ] AC2：对至少两个不同仓库成功出报后，「最近」列表可见两者；点非当前页条目可打开该条缓存小报。
- [ ] AC3：同仓点「重新出报」会发起 `GOSSIP_FETCH`；成功后列表与复开内容更新为新结果。
- [ ] AC4：重启浏览器（或清空页面后重开 GitHub）后，「最近」仍能打开重启前写入的条目（≤20）。
- [ ] AC5：失败出报不出现在「最近」列表。

## Out of Scope

- 面板宽度收缩 / 最小化窄条
- 小报正文分节折叠
- Web、CLI、popup/app 页的历史 UI 与同步
- 跨设备同步、云端历史
- 历史清空/导出 UI（可后续加）
- 缓存 TTL / 自动过期（MVP 仅条数上限）

## Technical Notes

- 实现落点：`apps/extension/content.js`、`content.css`；必要时微调 `manifest.json` 版本号。
- 存储键与条目形状见同任务 `design.md`。
- 复开渲染应复用现有 `showPanel` / `linkifyPlainHtml` 路径，避免第二套展示逻辑。
